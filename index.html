Analyse de transition

Du POC au MVP

L'effort bascule de la faisabilité vers la fiabilité.

  • Données : enrichir avec des cas d'urgence validés par des experts cliniques
  • Sécurité : intégrer des tests automatisés (red-teaming) pour bloquer les hallucinations dangereuses
  • Observabilité : monitoring réel via MLflow pour suivre la dérive en conditions réelles

Du MVP à la Production

L'enjeu devient la disponibilité et l'intégration.

  • Interopérabilité : communication avec le SIH via HL7 / FHIR (middleware complexe)
  • Infra : passage à une architecture multi-région pour garantir la haute disponibilité

🧠 Fine-tuning d'un LLM (Qwen3-1.7B)

Rôle : AI Engineer · Sujet : fine-tuning + serving d'un LLM open-source

Point de départ : design monolithique conteneurisé pour contenir toutes les briques du projet dans un seul conteneur.

Highlights

  • Architecture initiale monolithique conteneurisée, échec de déploiement (timeout vLLM ~240 s)
  • Refactor vers une architecture modulaire multi-stage : vLLM + modèle dans un conteneur, FastAPI dans un autre, UI dans un troisième, déployés sur Cloud Run (GCP)
  • Stockage des poids du modèle sur GCS
  • Bilan : la modularité a apporté découplage, observabilité et itération indépendante par brique

Évolutions proposées

  • Fusionner API + UI en un seul module pour alléger à 2 modules conteneurisés
  • Ajouter une base SQL pour la persistance des logs
  • Migrer l'UI de Streamlit vers React.js
  • Adopter une architecture agentique : cerveau LLM + orchestrateur LangGraph + outils (API, anonymisation, logging, suivi disponibilités lits/personnels, classifieur court-circuit)
